## 下一节点：Context 管理交互

暂停前只进行了只读调查，未修改源码，也未开始该节点的测试。
当前 `--context-repl` 仍只提供 Catalog 列表，不能把底层已有事务写成入口已完成。

恢复时先读 [Context 索引规格](subsystems/11-context-indexing.md)、
`src/cli.lua` 的 `parse_context_repl`、`src/main.lua` 的
`build_context_services` / `observe_context_catalog` / `management_service`，
以及 `test/fault/context_management_test.lua`。已有 registry 包括 inspect/search、
rename/rebind/delete、自动命名标记、import/repair/refresh；可复用现有终端输入与解析。

调查发现以下接入前必须处理的边界：

1. 当前 Catalog 投影不保留完整目标身份。执行动作前必须通过 Resolver 捕获并
   复核精确 TargetSnapshot；确认后再次复核，不能凭显示行重建目标。
   活动 writer 的 busy 元数据路径不得读取 Context 正文。
2. `src/context.lua` 的 `build_lifecycle_document` 接受调用者提供的 view digest，
   当前生命周期构建会生成 plain manifest。现有 fault fixture 的占位 digest
   不能直接用于 production。接入 mutation 前须生成可重建的真实 ModelView，
   并保留已接受的 compaction identity/projection；可复用或提取 `src/session.lua`
   的 `render_model_view`、`durable_compaction_projection` 与 publication 校验。
3. `store.repair` 会申请 writer，并可能在返回前恢复 previous 或清理文件，
   不能当作只读确认预览。需要先生成绑定来源与目标身份的只读计划，再确认、
   复核和执行；还须处理恢复后文件身份变化，不能通过锁龄强行解锁。
4. import 现有生命周期事件中的 Model/Permission mapping 属于审计数据，
   不会自动修改 Session 的有效选择。controller 必须实际校验并应用映射，
   不能仅写入审计后声称导入配置已生效。
5. rebind 必须验证目标 workspace 的逻辑路径与文件系统身份，并把 XML 迁移、
   生命周期事件、UpdatedAt、路径/hash 变化纳入同一事务；保留 CreatedAt。

上述是下一实现节点的调查结论，尚未形成 production controller 或完成证明。
