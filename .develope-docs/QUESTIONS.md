# 讨论问题队列

更新日期：2026-07-18

问题必须逐个讨论；当前问题确认后才推进下一项。

## 已确认 Q-001

Windows XP 与 CentOS 7 对首个发布版本属于硬性发布门槛、分级门槛，还是后续兼容目标？

结论：两者都是硬性发布门槛。参考目标为 Windows XP SP3 x86 与 CentOS 7 x86_64。

## 已确认 Q-002

旧 macOS 应属于硬性发布门槛、设计兼容但非发布门槛，还是明确不支持？如果是硬门槛，下一步再确定最低系统版本与 CPU 架构。

结论：v0.1 不承诺旧 macOS，当前只考虑旧 Windows 与旧 Linux 的专门兼容性。

## 已确认 Q-003

现代 Windows 与现代 Linux 应属于同等硬性发布门槛、基础冒烟验证，还是首版不建立正式承诺？

原结论后来由 D-012 修订：Windows 客户端矩阵包含 XP SP3、Vista SP2、7 SP1、8、8.1、10、11；所有最终声明支持的平台都执行完整测试，不设置只冒烟的支持层。Linux 的具体测试发行版以后确认。

## 已确认 Q-004

Windows 发布物采用一套贯穿 XP 至 11 的 x86 构建，还是为现代 x64 系统额外提供原生 x64 构建？

结论：Windows 只提供 Win32 x86 32 位构建，不提供原生 x64 或 ARM 构建。

## 已确认 Q-005

Linux 发布物也只支持 x86 32 位，还是保留当前 CentOS 7 / Debian 13 x86_64 目标？

结论：Linux 只支持 x86_64，不发布 i686 或 ARM 版本。原问题中的具体发行版清单后来依 D-012 延后确认。

## 已暂挂 Q-006

Linux 是使用一套在 CentOS 7 x86_64 上构建的低 glibc 基线通用产物，还是为不同发行版分别构建？

结论：这是 16 号打包发布系统的问题，延后讨论；无论选择何种构建策略，最终声明支持的平台都必须完整测试。

## 已确认 Q-007

平台兼容抽象采用“多个窄模块与显式依赖”“统一 platform 大门面”，还是“各业务模块内部自行判断平台”？

结论：采用多个窄模块与显式依赖。`main.lua` 负责组合，业务核心不直接判断平台。

## 已确认 Q-008

Windows/Linux 的具体能力实现由 `main.lua` 显式选择并注入，还是由每个公共模块在内部自动选择后端？

结论：由 `main.lua` 启动时一次选择后端并显式注入窄接口。

## 已确认 Q-009

Windows/Linux 独立发行包是继续共用一个 `main.lua` 入口并在启动时选择后端，还是各自维护平台专用入口文件？

结论：共用一个 `main.lua` 和业务源码；luainstaller 原生产物及外层资源按平台分别构建。
