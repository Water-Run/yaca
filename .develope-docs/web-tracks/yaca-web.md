# yaca-web 设计预留

更新日期：2026-08-10

状态：**空预留**；未开始决策包；禁止实现

## 产品意图

`yaca-web` 是 yaca 产品族中的 **本机本地 Web 表面**（local Web），用于在浏览器中使用与 TUI 同源的领域能力。

它不是 v0.1 的一部分，也不自动等于 remote 控制台。

## 已确认技术栈（D-058）

| 层 | 选择 | 说明 |
| --- | --- | --- |
| 服务端语言 / 平台 | **Java 8** | 语言级别与运行基线；不得默认依赖 Java 9+ 专属语法或 API |
| 浏览器 | 宽于 IE6（具体矩阵待开题） | 仍非现代 SPA 默认 |
| 与 `yaca-ie6` | **分栈** | IE6 线使用 PHP 5.4；本线不实现为 PHP |

约束：

- 不得把 JRE 打进 v0.1 核心 `yaca` terminal zip。
- 未批准前不默认绑定某一现代 Java Web 框架；宿主形态（嵌入式 HTTP、外置容器、独立进程等）待决。
- 与核心 yaca 的联接（本地 HTTP、IPC、文件旁路等）待决，但必须遵守单 writer / Permission / DoubleCheck。

## 与 `yaca-ie6` 的关系

- 同一产品族、同一本机信任与领域契约。
- 兼容基线 **宽于** `yaca-ie6`：允许在正式决策后采用比 IE6 更新的浏览器集合。
- 服务端 **不共享运行时**（Java 8 vs PHP 5.4）；对齐靠共享协议与验收语义。
- 不得要求用户必须使用现代-only 特性才能完成核心旅程；与 IE6 线冲突时，以 **共享领域协议 + 更严兼容线** 为优先裁决参考。
- 前端实现上可以是“共享协议 + 两套资源”，或“一套资源 + 能力探测降级”；**尚未选择**，开题时比较。

## 待冻结（开题清单，非现行契约）

以下仅作预留提纲；**服务端语言已定为 Java 8**，其余未决：

### 产品旅程

- [ ] 启动方式：显式 CLI action / 独立 executable / 与 TUI 并存？
- [ ] 默认是否仅 loopback；是否允许用户显式绑定其他地址（默认应拒绝）
- [ ] 是否提供只读状态页，还是完整交互（对话、审批、配置浏览）
- [ ] 与 chat / model-repl / config-repl / context-repl 的对应关系

### Java 8 服务端

- [ ] 进程模型：独立 JVM 进程 vs 其他宿主；如何发现/停止
- [ ] HTTP 栈白名单（仅 Java 8 可移植子集）
- [ ] 与核心 yaca 的协议载体（JSON/表单/SSE 等）及背压
- [ ] 打包：JRE 捆绑策略、平台矩阵、许可证
- [ ] 构建工具链是否允许（Ant/Maven 等）及是否禁止仅新 JDK 可用的插件

### 浏览器与资源

- [ ] 正式支持浏览器矩阵（不得默认等同 Chrome-only）
- [ ] 是否允许任何 ES5+ / CSS 能力；与 `yaca-ie6` 的共享/分叉点
- [ ] 静态资源布局、缓存、版本、CSP（若适用）策略
- [ ] 是否禁止前端框架（默认倾向：是，与项目风格一致）

### 安全

- [ ] 本机身份：是否需要 token / 随机 path / 一次性 secret
- [ ] Origin / CSRF / 跨站请求防护
- [ ] 秘密（API Key）在页面上的显示/复制规则
- [ ] 与 Permission 审批、DoubleCheck、busy cancel 的页面投影

### 运行时耦合

- [ ] 是否与 TUI 同进程；单 active Context writer 如何保持
- [ ] 流式模型输出在浏览器中的背压与断线
- [ ] 非 TTY / 无 TUI 时 Web 是否可单独成为主表面

### 发布

- [ ] 独立 zip 还是可选组件
- [ ] 与 Win32/Win64/Linux 三目标矩阵如何对齐
- [ ] self-test 是否包含 Web 阶段（默认：独立产品线自有证据）

## 明确非目标（除非另行重开）

- 公网托管的多租户 SaaS 控制台
- 默认 LAN/remote 无认证监听
- 借 Web 复活 MCP/plugin/hook 扩展面
- 把图像/音频/TTS 等仍被 D-044 排除的能力偷渡进 Web
