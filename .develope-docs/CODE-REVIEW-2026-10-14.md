## R96 维护装配器的 Git 来源

按 D-089 从 R95 继续。同步远端无新增，已有候选仍绑定 `e06d9f9`，本轮不改动产品
核心，也不修改已发布 R95 的附件或资格范围。

核对发现，两 Windows full 维护装配器仍将 PortableGit 二进制安装包复制到 sources，
R95 的真实来源替换只存在于当时的交付脚本。本轮取消该回退，要求显式提供匹配
版本的 Git source-profile 和完整档案 SHA-256；在创建输出前验证身份、成员和摘要。
源码档案内即便有正确的成员摘要，编译文件也不能充当来源。来源状态随工具记录保留，
结构检查不自动提升为 complete。原未使用的 payload-cache 参数移除，调用入口见执行手册。

两 full 收集器也统一输出正斜杠归档路径，避免 Windows 构建机产生不可接纳的
反斜杠 metadata。相关读取、复制、忽略回调及 main 的注释按实际行为重新核对，
包括修正“忽略项”被误写为“保留项”的返回语义。

反例基线 7/11，修复后 11/11；追加归档路径检查后 12/12，Windows 原生 Python
也实际通过 12/12。真实 R95 Win32/Win64 来源档案均重新验证通过且保持 partial。
完整 Lua 735/735、完整 coding readiness PASS；全仓结构 270/5771/0。
人工核对限于本轮变化声明与相关维护模板，全仓语义 Review 仍为 partial。

## 精确来源恢复

Win64 缺少原来源包的 44 条清单项归并为 38 个精确版本来源配方。本轮先从 GFW
缓存的历史 Git 树恢复原配方，再补 MSYS2 官方上游；原 GFW GCC 配方停留在 7.3，
不能代填实际 14.2。38 个配方及各自补丁已经按原 Git blob 字节身份核对。

首轮来源载荷恢复：13 个配方的静态源数据摘要全部核对，15 个恢复了经摘要核对的
静态子集，10 个仍有变量、VCS、传输或摘要问题。子集保留签名/VCS 缺项；
包与已交付二进制之间的完整对应关系仍待人工核对，不把配方恢复或结构通过写成
完整来源闭包。动态配方只作为数据读取，不在开发宿主执行 PKGBUILD。
