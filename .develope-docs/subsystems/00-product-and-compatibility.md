# 00 产品契约与兼容性基线

状态：讨论中

## 职责

定义 yaca v0.1 是什么、在哪些环境必须工作、什么结果才允许发布，以及哪些能力明确不在首版范围。后续所有子系统必须服从这里的约束。

## 已确认

- yaca 是单 Agent、终端优先的 Coding Agent。
- 主体使用官方 Lua 5.5 语言级别与 ABI。
- Windows XP SP3 x86 是 v0.1 硬性发布目标。
- CentOS 7 x86_64 是 v0.1 硬性发布目标。
- v0.1 不承诺旧 macOS；不建立旧 macOS 专用实现与发布测试矩阵。
- Lua 程序由 `../luainstaller` 打包；发布物不得依赖系统已安装 Lua。
- 设计先于编码，实施时按子系统逐个推进。

## Windows 客户端矩阵

| 系统 | 最低版本 | 验证等级 |
| --- | --- | --- |
| Windows XP | SP3 | 完整兼容闭环，硬门槛 |
| Windows Vista | SP2 | 发布冒烟，失败阻断发布 |
| Windows 7 | SP1 | 发布冒烟，失败阻断发布 |
| Windows 8 | 正式版 | 发布冒烟，失败阻断发布 |
| Windows 8.1 | 正式版 | 发布冒烟，失败阻断发布 |
| Windows 10 | 受测版本记录在发布证据中 | 发布冒烟，失败阻断发布 |
| Windows 11 | 受测版本记录在发布证据中 | 发布冒烟，失败阻断发布 |

当前不承诺 Windows Server、Windows 2000 或 ReactOS。

Windows v0.1 只发布 Win32 x86 32 位产物。x64 Windows 使用系统的 32 位兼容环境运行；不提供原生 x64、ARM 或 Windows on ARM 支持。

## 当前边界

- “支持”必须包含目标环境上的打包产物启动、模型请求、至少一个工具调用、上下文保存与恢复。
- 不能只凭现代系统测试推断旧系统兼容。
- Web 不进入首版关键路径。

## 当前讨论点

Linux 发布物的 CPU 架构尚未确认。当前文档把 CentOS 7 与 Debian 13 写为 x86_64，而仓库中的 Linux 随包工具主要是 32 位 x86；需要明确 Linux 是否也收敛到单一 32 位架构。

## 验收设计方向

每个硬性目标都需要独立构建记录、干净环境运行记录和功能闭环记录。详细矩阵在本子系统确认后形成。
