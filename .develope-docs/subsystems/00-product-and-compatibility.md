# 00 产品契约与兼容性基线

状态：讨论中（兼容性基线已确认，产品闭环待确认）

## 职责

定义 yaca v0.1 是什么、在哪些环境必须工作、什么结果才允许发布，以及哪些能力明确不在首版范围。后续所有子系统必须服从这里的约束。

## 已确认的兼容性基线

- yaca 是单 Agent、终端优先的 Coding Agent。
- 主体使用官方 Lua 5.5 语言级别与 ABI。
- Windows XP SP3 x86 是 v0.1 硬性发布目标。
- CentOS 7 x86_64 是 v0.1 硬性发布目标。
- v0.1 不承诺旧 macOS；不建立旧 macOS 专用实现与发布测试矩阵。
- Lua 程序由 `../luainstaller` 打包；发布物不得依赖系统已安装 Lua。
- 设计先于编码，实施时按子系统逐个推进。

## Windows 客户端矩阵

| 系统 | 最低版本 | 验证等级 |
| --- | --- | --- |
| Windows XP | SP3 | 完整测试，硬门槛 |
| Windows Vista | SP2 | 完整测试，硬门槛 |
| Windows 7 | SP1 | 完整测试，硬门槛 |
| Windows 8 | 正式版 | 完整测试，硬门槛 |
| Windows 8.1 | 正式版 | 完整测试，硬门槛 |
| Windows 10 | 具体版本以后记录 | 完整测试，硬门槛 |
| Windows 11 | 具体版本以后记录 | 完整测试，硬门槛 |

当前不承诺 Windows Server、Windows 2000 或 ReactOS。

Windows v0.1 只发布 Win32 x86 32 位产物。x64 Windows 使用系统的 32 位兼容环境运行；不提供原生 x64、ARM 或 Windows on ARM 支持。

Linux v0.1 只发布 x86_64 产物，CentOS 7 x86_64 是旧 Linux 兼容基线；不提供 i686 或 ARM 产物。最终支持的发行版清单以后确认，列入清单的每个平台都执行完整测试。

## 当前边界

- “支持”必须包含目标环境上的打包产物启动、模型请求、至少一个工具调用、上下文保存与恢复。
- 不能只凭现代系统测试推断旧系统兼容。
- Web 当前按暂缓跟踪；是否正式排除出 v0.1 及恢复条件由 `PROD-11` 确认。

## 尚未确认的产品契约

兼容性目标不等于完整产品设计。[`../DESIGN-CHECKLIST.md`](../DESIGN-CHECKLIST.md) 的 `PROD-*` 仍需逐项确认：首次安装到恢复会话的完整闭环、自主性和完成定义、工作区/Git 模型、数据分类、离线与性能承诺，以及 v0.1 的明确非目标。这些结论会反向约束所有子系统，因此 00 号系统不能整体标记为“设计已确认”。

## 延后事项

具体测试机器、Linux 发行版矩阵、构建主机和通用包/分发行版包策略，统一延后到 16 号打包发布系统设计。

## 验收设计方向

所有最终支持目标都需要独立构建或产物来源记录、干净环境运行记录和完整功能闭环记录。不使用“只冒烟”代替支持验证。
