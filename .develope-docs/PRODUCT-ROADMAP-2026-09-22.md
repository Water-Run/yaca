# yaca 通用 Agent 定位与可用版本路线

日期：2026-09-22。依据：本次负责人要求、当前源码、指定服务器复核及三个上游的源码阅读。

**yaca 是简单、鲁棒、便携的通用终端 Agent，重视老设备兼容与开箱即用。**
它根据用户目标理解上下文、调用工具、完成工作并验证结果，适用于代码辅助、文件与
数据处理、脚本自动化、系统问题辅助等任务。名称保留 Yet Another Coding Agent。

负责人后续明确：“只是通用的Agent, 正好老设备高度兼容, 正好开箱即用”。
U 盘插入旧设备直接运行是检验产品特性的典型场景，不限定用户、安装介质或任务类型。
不能把 yaca 收窄成排障产品，也不以长程开发工具的全部复杂度作为通用能力的前提。

与原版相比，定位和主体架构基本不变。明确新增的是可被 Agent 调用的同版本 Lua，
以及可选 tools 的携带/说明约定；其他工作以原有兼容性承诺的修补和验收为主。
大改蓝图第 0 节已收紧范围，Lua 内嵌与三档发行已由 D-073 明确；其他改型/协议/默认值/拆模块不列为前置。

本文区分负责人明确的方向、源码/实测事实和下一版实施建议。
本次完成定位、调研与基线复核；下列新能力尚未实现，不能据此宣称发行可用。
机读状态仍为 `implemented-unqualified`，Release Gate R 关闭。

## 1. 服务对象、任务和产品边界

用户可以在自己的电脑、服务器、旧业务设备或受限内网中使用 yaca。
现代机器同样属于使用范围；兼容旧系统是运行能力，不是选择任务的条件。
无需先装一套现代开发环境，实际能力由模型、权限和可用工具共同决定。

| 工作负载 | 典型任务 | 应交付的结果 |
| --- | --- | --- |
| 代码辅助 | 阅读代码、实现修改、维护 Lua/Python/批处理、运行已有检查 | 变更和可复核的验证结果 |
| 文件与数据 | 搜索整理文件、分析文本/日志、比较配置、转换数据 | 有来源与范围说明的结果或产物 |
| 自动化 | 编写并执行脚本、批量处理、调用已有命令行工具 | 可观察、可取消、效果明确的操作 |
| 环境与问题辅助 | 服务异常、端口冲突、配置错误、旧系统操作 | 证据、判断、执行与复验 |
| 解释与协作 | 根据本地材料解释问题、制定步骤、澄清任务 | 有依据的回答及下一步 |

任务可以有多轮和多个步骤；不人为限制为排障或短脚本。优先打磨常用任务和即时可用性，
本轮暂不增加为多日自主开发服务的分支调度、后台任务或多 Agent 编排。

“高度可用”在这里指启动成功、环境依赖少、等待有界、故障可解释、任务可恢复。
不以常驻服务、集群或后台调度作为这个版本的目标。
继续保持单 Agent、单 active Context、单 workspace、串行工具及终端交互。
Web、MCP、插件市场、子 Agent、自动更新、遥测和完整开发工作台不进入本轮。

## 2. 把开箱即用写成可验收的旅程

标准包准备完整后，可放在本地磁盘、服务器目录或 U 盘，在支持的目标机直接运行：

```text
本地 CMD：进入程序目录，运行 yaca.exe
Cygwin SSH：进入同一目录，运行 ./yaca.exe
指定工作目录：yaca.exe C:\work
```

1. 已配置模型时，直接进入可输入状态；不要求运行 Install.cmd，不要求管理员权限。
2. 未配置模型时，在同一次启动中进入简短配置引导；复用已有隐藏 Key 输入和配置事务。
   先问完整 endpoint、model、key，其他字段给出可检查默认值和高级入口。
   新会话仍以调用目录为 workspace；程序、工具、配置路径以 executable 所在目录为基准。
3. 启动展示简短事实：当前工作目录、模型/网络是否可用、权限档及诊断入口。
   工具版本、环境编码、实际 shell 等事实给 Agent 一个有界摘要，避免反复猜测环境。
4. 缺网或模型不可达时，配置、帮助、状态、自检、已有报告读取仍可用；给出故障层级。
   云模型不可达就不能继续推理；便携运行不意味着附带离线大模型。
   可预配用户自己的内网模型服务/网关，切换时明确显示目的地。
5. 用户给出任务，Agent 获取必要上下文，调用可用工具完成工作，最后说明结果及验证范围。
   正常退出后程序可整体移动；取消和失败不冒充任务完成。

**本次已证明当前预览尚不满足第二种启动方式。** `ssh -tt` 下直接 chat 返回
`TtyRequired`；经 `winpty cmd` 后离线自检通过。下一版需由程序处理这一终端差异，
不能把人工补一条 winpty 命令当作最终体验。普通重定向管道仍需与交互式 PTY 区分。

## 4. 内嵌 Lua 与三档发行

负责人已明确解释器仍内嵌 yaca，每个平台提供 clean、std、重版本三档；
重版本选择开发工具箱，暂命名 full。原三个目标共九个计划包，同平台三档的
核心二进制完全相同，仅 tools 组合不同。

| 版本 | 分发内容 |
| --- | --- |
| clean | 仅 yaca.exe（Linux 为 yaca），内嵌 Lua 及核心必要依赖 |
| std | clean + Python 2.7、SSH/SCP/SFTP、curl、7-Zip |
| full | std + Git、Python 3、C/C++ 编译/构建工具及 SQLite/jq/文本工具；按平台兼容性取舍 |

版本号、来源、XP/Win7/Linux 差异及资格边界统一维护在
[发行分档与默认工具清单](../release/TOOL-BUNDLES.md)。
clean 分发时没有 tools 或旁置 lua.exe/Lua DLL；配置与历史仍在运行后生成的 __yaca__。
此前独立 Lua 文件/onedir 的建议由此取代，保留现有自包含打包基础。

### 同一个程序内的解释器

Lua 取 `release/dependencies.lock` 的同一完整版本，当前为 5.5.1。
建议由 yaca 自身提供 `--lua` 解释器模式：执行脚本、参数、单段代码或 stdin；
这仍是待实现接口。Agent 用现有 exec 启动同一个 yaca 的新进程，继承统一输出、
超时、取消与进程回收机制，不把脚本注入主 Agent 的 Lua 状态。
解释器模式不要求模型配置、聊天 TTY 或 tools，不读取核心秘密，不递归启动 AgentLoop。
它拥有普通进程能力，沿用 Shell 权限；内嵌不等于沙箱。

### tools 的交付与使用

std/full 各有默认清单；用户可选择 clean，也可自行增删 tools。
程序把实际工具名称、版本、位置和用法告诉 Agent，不引入插件、强制注册或自动安装。
系统已有工具同样可以用，摘要区分来源。核心联网不借用 Python 2 的 SSL 或工具目录。
工具组件必须有完整依赖、许可/来源与目标验证，不把安装器或开发机目录当便携证明。
Python 2.7 是兼容工具；full 的 Git、Python 3 和编译器按平台选型并如实说明限制。

### 绿色运行与旧数据

进程局部环境不修改系统 PATH、注册表或服务。移动目录、盘符变化、中文/空格路径、
只读介质、空间不足和 TEMP 不可写均要测试；不可写时给出可执行说明，不静默另存用户目录。
U 盘跨机器不自动恢复另一台机器的任务；workspace 身份校验和显式继续保持。
FAT32/exFAT 的锁及替换语义独立验证，不能套用 NTFS 的结论。
Key 与历史随目录移动的事实应在配置说明中明确，公开发行包保持无凭据。

## 5. 老环境网络的完整路径

主链路保持 `模型适配 → yaca 网络端口 → 随包 curl + Mbed TLS + CA → 配置的 endpoint`。
Python/OpenSSL/系统浏览器是否能联网，不作为 yaca 是否能连接模型的前提。
现有 XP 候选是 blocking IPv4；TLS 最低版本、CA 和 API 基线以锁定闭包和实测为准。

| 故障层 | 应呈现的信息与处理 | 验收办法 |
| --- | --- | --- |
| 本机 | 组件缺失/哈希不符、证书文件不可读、明显错时钟 | 离线说明具体组件；不先发模型请求 |
| DNS/TCP | 名称解析失败、拒绝连接、不可达、连接超时 | 故障 DNS/黑洞端点；外层总截止时间能结束 blocking resolver |
| 代理 | 当前采用的路由来源、去凭据地址、认证失败 | 直连、HTTP CONNECT、带认证代理、NoProxy 分别验证 |
| TLS | 信任链、域名、日期、协议错误 | 自签/过期/错主机/企业 CA 对照；保留证书校验 |
| HTTP | 401/403、404、407、429、5xx | 区分 key、URL、代理和临时服务故障；尊重有界 Retry-After |
| 模型协议 | HTML 登录页、无 tool calling、畸形 SSE/JSON | 报告协议不符与修复入口，不当作普通模型答复 |
| 流式中断 | 已接收前缀、是否完成工具调用、能否重试 | 首事件前断线、可见文本后断线、tool 参数中断分别测试 |

网络错误说明必须在不向模型询问的情况下生成。代理密码/key 不进入命令行、普通诊断
或 Agent 环境摘要；核心仍使用已有匿名 secret carrier。
自定义 CA 是显式配置，不覆盖系统证书库，不用 `--insecure` 或自动 HTTP 降级兜底。
PAC/NTLM、IPv6、TLS 检查代理等能力按实际构建声明支持范围；现有精简构建不能凭“curl 支持”
就承诺支持这些特性。必要时由用户显式配置可达的内网网关。

一个逻辑模型请求只有一个重试预算 owner；curl 的自动重试保持关闭。
已有 canonical event 后不透明重放请求，不自动重跑任何结果未知的工具。
本地状态显示下一次重试时间、次数和取消入口；断网时仍能立即取消等待。
流式降级只沿用已经实现的明确适用边界，不在半条工具调用后补执行。

## 6. 保持核心简洁与可证明

读源码后的选择见[对照记录](references/agent-loop-source-review-2026-09-22.md)。
MiniMax 的清晰采样边界、ZCode 的流式重试边界、DeepSeek 的事实发布/取消收尾值得借鉴。
这些原则中不少已在 yaca 实现；下一步以补实机故障用例为主，不另造事件框架。

核心保持下列顺序：

```text
接收输入并持久化 → 冻结配置/权限/预算 → 构建模型请求
    → 校验完整响应 → 串行工具：权限 → intent → 执行 → result
    → 下一次请求，或明确结束/等待用户
取消/失败 → 停止新操作 → 收拢已启动进程 → 已知结果或 unknown → 恢复终端
```

必须守住的条件：

1. tool call/result 保持配对。未执行、被拒绝、取消、执行失败、效果未知分别表达。
2. 完成只能来自真实结果；预算用尽、模型截断、review 不确定不能被包装成完成。
3. 配置/模型/权限在 turn 接纳时冻结。管理界面修改仅从后续 turn 生效。
4. 持久化结果未明时停止有副作用的工作；重开不自动重放。提供“检查现场后新开任务”
   或受控恢复入口，不要求用户手工改 XML 消除 unknown。
5. 网络、脚本、输出、上下文与恢复均有上限。操作开始前预留可落盘的结果/终态容量；
   文本投影说明截断范围，不能把截断当完整观察。逻辑预留不替代磁盘失败处理。
6. 大文件范围读取/搜索；输出预算在采集时生效。先不引入永久 artifact 数据库。
7. 已有单 XML 与模型视图压缩继续保留。先测慢 U 盘每轮重写成本，再局部优化序列化/复制；
   不为长程开发预先引入 WAL、SQLite、session 分支和通用 undo。

`main.lua` 的职责提取不是本轮交付前置条件。修具体问题时确有收益再局部提取，
复用同一 Runtime/Session owner，保留行为回归。

本轮保留当前 `Agent.DoubleCheck=true` 及其他默认值。额外模型往返的优化需要
先有任务对照数据，不因增加 Lua/tools 就改审查策略、权限或历史行为。

## 7. 顺序实施计划

以下 F 编号保留作工作分类，按具体缺陷与依赖推进，不要求每一类都新增机制。
每批产出能检查的结果；已有能力只做复核，不把历史 C01--C31 重新标为未完成。

| 包 | 工作与主要影响面 | 退出条件 |
| --- | --- | --- |
| F0 契约增量 | 同步实际引入的 Lua、可选 tools、包允许项与用法说明；其他契约按代码变更涉及范围同步 | 不重写无关契约；能力与包一致，Gate R 仍关闭 |
| F1 直接启动 | `native/yaca_native.c`、`terminal.lua`、`cli.lua`、`main.lua`；PTY/console 适配、同次首次配置、启动故障提示 | 本机 CMD 与指定 Cygwin SSH 都从 `./yaca.exe` 进入/退出；不依赖人工 winpty；隐藏 Key、中文、取消、EOF 正确 |
| F2 网络闭环 | `network.lua`、`model.lua`、`diagnostics.lua`、self-test；上述网络故障矩阵及有界等待 | 真实服务器直连/代理/自定义 CA 可验证；断网错误可定位；取消/重试不重复工具 |
| F3 Lua 与三档发行 | 内嵌解释器模式、三档装配、release 清单、进程/工具能力摘要 | clean 仅 yaca；Lua 同版本可调用；std/full 各工具按平台验证；三档核心一致 |
| F4 缺口修补 | 先复现容量/恢复边界；按实际任务需要补文件/编码支持，优先保留原格式/接口 | 所修问题有回归证据；容量不足不先执行，未知结果不重放 |
| F5 局部优化 | 依据实测处理重复逻辑、无进展循环与资源瓶颈；保留核心架构与默认值 | 有明确收益和回归证据，不以拆模块数量验收 |
| F6 发行资格 | 接续 C32--C34；干净机、U 盘、三目标完整矩阵、许可证/SBOM/源码与包哈希 | 只发布有对应目标证据的能力，最终按原三目标规则评审 Gate R |

F1 先做 Cygwin PTY 的小型技术验证：原生行式适配或自动进入随包桥接，由隐藏输入、
取消与退出实测决定；不能仅检查 `TERM` 环境变量就把任意 pipe 当作可信交互终端。
旧系统没有新式 console API 时，要同时证明等待线程/子进程可回收。
这一技术验证不扩展公共 headless/remote API。

F4 的编码范围先覆盖目标机实际 ACP/OEM 与 CP936、UTF-8、UTF-16。
显示解码与原始字节分开；编码未知时显式指定，不猜测后静默改写。
无法无损编码的替换应拒绝；CRLF、BOM、文件身份和 raw digest 继续参与校验。

可能受实际变更影响的传播清单（不是预先全部重写）：`contracts/product.lua`、`release.lua`、`platform.lua`、`tui.lua`、
`tools.lua`、`prompts.lua`、`diagnostics.lua`、必要时 `config.lua`；
`release/manifest.lua`、`dependencies.lock`、`release/luainstaller.lua`；
`.tools/qualification/windows_package.py`、Windows/Linux builder 与 package-layout/loader/golden 测试。
`coding-style.txt` 中 Lua 5.5.0 的写法也需与共同构建版本规则统一。
本次没有更改这些机读契约或产品代码，防止文档计划冒充已实现能力。

## 8. 可用版本的验收标准

以可重复任务而不是新增功能数量验收。每份证据记录 exe/包哈希、系统/位数、账户、
终端入口、介质/文件系统、代理/CA 类别、任务结果和退出后遗留物；不记录明文凭据。

| 验收组 | 必测场景 |
| --- | --- |
| 干净启动 | 无系统 Lua/Python/curl/Git、最小 PATH、无配置/预配置、标准用户、无可写 TEMP |
| 真实入口 | 老 CMD、指定 SSH PTY、中文/空格目录、从另一 cwd 调用、退出后终端恢复 |
| U 盘 | 实际 USB 介质、NTFS 与计划支持的 FAT32/exFAT、移动目录/盘符、缺工具/只读/空间不足 |
| 可选工具 | 无 tools、只带 Lua、选配 Python/SSH、用户自备工具、工具缺失后的能力说明 |
| 网络 | DNS/连接/TLS/代理/认证/限流/半截 SSE；直连和预配内网服务；等待时取消 |
| 通用任务 | 代码修改与验证、文件/数据处理、脚本自动化、材料解释；另测日志定位、配置修复等诊断场景 |
| 故障 | 脚本挂起/派生子进程/超大输出、工具返回后落盘失败、退出/杀进程后恢复、不重放未知操作 |
| 兼容性 | XP SP3 x86、Win7 SP1 x64、CentOS 7 x64 原硬门及声明覆盖的完整矩阵；Server 2008 单列 |

首批任务在可丢弃工作目录/服务样本中验证，不用真实业务系统充当故障注入场。
当前服务器安装过 Python 等工具，不能拿它一台的通过结果证明“干净机零依赖”。

性能先收集同一台机器的冷启动、首个可输入时间、取消响应、峰值内存、Context 保存耗时
和写入量；分别测本地盘与 U 盘。发布 hard caps 按这些证据校准。
首批体验目标可用“正常可写介质数秒进入输入、配置齐备后无需额外准备、短任务有限往返”
指导优化；也测多轮任务的容量/取消边界，不人为限定任务长度。
实测前不宣传具体 SLA、包大小或最大兼容范围。
