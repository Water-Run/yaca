## B-07 流式网络、TLS、重试与自动切换

建议流式响应是正式能力，非流式是 provider 能力降级。接收任何响应事件后，不自动重发整次请求；传输层只在尚无响应且错误明确可重试时退避，并受总预算约束。模型/provider 失败时默认不自动 fallback，避免悄悄改变费用、隐私和行为。

模型 provider 网络与 Agent 工具网络应分开授权。TLS 建议使用随包 curl/CA 的可复现基线，并允许显式用户 CA；key 通过 stdin 或受控临时配置传递，不进入 argv。启动和本地浏览不隐式联网。

## B-12 “完整对话”的真正含义与 XML 数据角色

建议把“完整”定义为完整保存受 schema 和上限约束的规范事件，而不是无上限保存所有原始字节。XML 中明确分区 metadata、events、model_views、session_parameters 和 audit_summary；事实事件包含用户输入、完成/中断的模型消息、工具调用与真实/合成结果、审批、终止评估、压缩和 turn 边界。

大工具输出先由工具层形成 canonical result，记录原始大小、截断/引用和摘要；XML 完整保存这个规范结果。流式残片可以保存为 `incomplete` 诊断事实，但不作为完成 assistant 消息送入下一请求。隐藏推理、secret header 和无限原始输出不属于“完整对话”承诺。

: 最佳实现的XML, 理论上拷贝XML就等于可以在另一台机器继续开工--完整接盘信息. 合适的高性能lua xml库.

关联：`CTX-01`、`CTX-02`、`CTX-07`、`CTX-23` 至 `CTX-25`。

## B-13 单 XML 高频写入、Sidecar 与崩溃恢复

这是当前存储设计最关键的技术门槛。每个事件都整体重写长 XML 会产生 O(n²) I/O 和 Win32 x86 内存峰值；但分段目录又违反已经确认的“单 XML 是活动事实源”。

建议 v0.1 先采用正确性基线：只在完整 canonical event 边界提交，不保存 token delta；每次把旧 XML 流式复制到临时文件，在根结束标签前插入新事件/commit footer，flush、重新验证后通过平台已证明的原子替换或等价可恢复协议发布。它不会把整份 XML 同时装入内存，也不会产生半个正式文件，但每次提交仍有 O(文件大小) I/O，因此必须设置大小/延迟预算并做旧机实测。

普通 well-formed XML 不能在已经写完根结束标签后“直接追加一个事件”而仍保持合法，所以不能把这种做不到的操作写成承诺。如果基线实测不达标，需要项目负责人再明确允许短期 WAL/recovery sidecar，或调整“单 XML 是唯一活动事实源”的决定；不能暗中引入第二份长期事实。每个副作用仍必须在执行前先持久化 operation，结果在下一采样前持久化。

: 合适的库, 详细的测试.

关联：`FMT-01`、`CTX-03`、`CTX-08`、`CTX-16`、`CTX-21`、`CTX-22`。

## B-14 上下文解析、浏览器、重命名与删除

浏览器从当前镜像目录进入，支持面包屑、上级、根、显式全局搜索、详情、刷新、重命名和删除。重命名首版只改同目录 basename；跨目录/工作区重绑定是独立动作。删除默认进入不参与 Resolver 的回收区，恢复和永久清除分开；活动 XML 外部丢失时句柄立即 stale，阻止继续写入，不按内容猜新位置。

## B-15 压缩机制

建议采用“事实历史 + 结构化检查点摘要 + 最近原文窗口”。压缩只重建下一次模型视图，不删除或改写 XML 的事实历史；摘要记录来源 event seq/digest、模型、版本和代次。必保槽位至少有目标、用户决定、限制、文件改动、验证结果、未知副作用和未完成事项。

达到模型窗口的安全阈值时提前压缩，provider 报超限只作为补救。摘要失败、仍超限或连续无收益时保持旧视图并停止循环；默认使用当前模型，专用压缩模型以后可配置但必须记录且不自动换 provider。

: 最合适的方式. 简洁而有效即可.
超限提示 如果配置中, 有更大上下文的配置 进行推荐
留意XML存储完整信息--包括Model的切换(模型也要知道原来是什么, 现在换成了什么在Prompt中)
如果先前的Model上下文足够长, 优先提示.

关联：`COMP-01` 至 `COMP-10`、12 号压缩子系统。

## B-16 TUI 规范形态、输入与浏览器风格

建议所有平台以追加式逐行 transcript 为规范界面：plain 无 ANSI 仍能完成全部核心动作，basic 只增强颜色/临时状态行，v0.1 不承诺全屏、鼠标和自定义快捷键。enhanced renderer 只能改变表现，不能改变动作、默认值、确认或错误结果。

正文使用稳定 ASCII 标签 `USER/ASSISTANT/TOOL/STATUS/WARNING/ERROR/ACTION REQUIRED`。plain 使用系统 cooked line；多行输入有显式开始/结束语法，bracketed paste 只是增强；以点开头的普通消息有固定转义；秘密不进入历史。工具输出默认摘要和头尾截断，完整规范结果在存储层；配置与上下文浏览器共享 help、面包屑、搜索、详情、back/discard 语义。

: 不需要鼠标和自定义快捷键 yaca很简单 快捷键直接在help中显示.
基本就是刚刚提到的几个和必须的了.

关联：`TUI-*`、14 号 TUI 子系统。

## B-17 编码、语言、无障碍与旧终端

建议内部协议、配置、XML 和机器输出统一 UTF-8；Windows 文件系统通过窄原生适配器使用宽字符 API，不能假设 Lua 标准 `io/os` 足够；控制台输入/显示单独转换，显示替换不得改变真实路径或 hash 输入。Linux 上不能解码为 UTF-8 的原始文件名字节必须由路径层以 opaque/escaped 形式表示，不能伪造为另一个 Unicode 名称。重定向和机器输出固定 UTF-8，不跟随控制台代码页。

UI 语言、模型回复语言、配置键名和机器字段独立；机器字段固定 ASCII。线性 transcript 是屏幕阅读器规范顺序，状态按句/块播报而非逐 token，所有含义都有文字标签，并提供显式无颜色、无动画和高对比模式。能力未知、`TERM`/terminfo 失败、尺寸/宽度不可靠时回到 plain 单项多行布局。正常退出和崩溃都 best-effort 恢复 QuickEdit、raw mode、光标、颜色和代码页。

: 只需要支持英文, 内部不使用ASCII之外的字符. 不需要提供各种显示模式切换, 保持简单, 移除vivid

关联：`PLAT-09` 至 `PLAT-12`、`PROD-15`、`TUI-12` 至 `TUI-17`、`TUI-27`。

## B-18 错误、重试、日志与隐私

建议全局 typed error 包含稳定 ID、类别、阶段、可重试性、用户说明、技术 cause 和安全元数据。用户错误卡片必须说明发生了什么、已保存什么、可能副作用、能否重试和下一步。同一根因只由责任层显示一次主错误；自动重试显示原因、次数、倒计时并可取消，部分成功逐项列出成功、失败和 unknown。

默认 info 日志只保存阶段、ID、耗时和结果；请求/正文 trace 显式开启。上下文 XML 保存会话审计和日志级别快照，完整诊断写独立轮换日志。v0.1 不做远程遥测；支持包先预览，默认不含 secrets、上下文正文和原始请求。

: 保持简单, 文件只有ini和xml. 重试之类的和配置Model绑定, 是否走代理之类的则是全局

关联：`DIAG-01` 至 `DIAG-13`、`PROD-08`、`SAFE-09`。

## B-19 `__yaca__`、发布形态与升级

建议安装程序/发行资源与用户数据分离；正常安装把配置、secrets、上下文和日志放可写用户数据位置，只有显式便携模式才放发行目录旁。v0.1 先正式支持便携目录包，安装脚本只是薄层，单文件发行延后；Windows x86 与 Linux x86_64 始终分别打包。

程序、配置 schema 和上下文 schema 三种版本独立演进。程序可回滚；配置/上下文迁移先备份、流式写新文件、验证后替换，失败不破坏原文件；新版数据在旧程序中只读或明确拒绝。v0.1 不自动检查或安装更新。

: Release在一个.zip包, 各个系统版本独立

关联：`PLAT-02`、`REL-01` 至 `REL-13`、`UPDATE-01`、`UPDATE-02`。

## B-20 性能、测试、供应链、文档状态与扩展
