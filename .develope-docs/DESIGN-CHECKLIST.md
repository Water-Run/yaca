# 全产品设计决策清单

更新日期：2026-07-18

状态：第四轮跨系统接缝审阅完成，共 354 个独立设计 ID，待按依赖确认

## 用途

本文件列出 yaca 在编码前需要由项目负责人决策的完整主题。它是问题地图，不是已经确认的设计，也不要求一次回答全部问题。

讨论分两轮：

1. **系统契约轮**：先确认用户体验、生命周期、数据语义、状态、失败恢复、安全和旧平台降级。
2. **实现契约轮**：系统契约确认后，再确定接口形状、数据格式、算法、模块布局和测试细节。

参考项目只用于发现成熟实现已经遇到的问题，不自动成为 yaca 的设计结论。每次只深入一个主题，给出方案、取舍与推荐，由项目负责人决策后写入对应子系统文档和 `DECISIONS.md`。

## 优先级

- **P0**：会改变产品行为或后续多个系统边界，必须最先确认。
- **P1**：影响一个子系统的完整契约，在实现计划前确认。
- **P2**：实现和发布细节，可在系统行为稳定后确认。
- **暂缓**：明确不进入 v0.1，但记录重新评估条件。

## 建议讨论主线

1. 产品闭环与 Agent Loop。
2. 上下文的完整历史、恢复、索引与压缩。
3. 工作区指令、工具、改动事务与权限。
4. 配置、秘密、模型注册表与默认项。
5. CLI/TUI 的交互流程和视觉语言。
6. 模型协议、网络、进程、平台和数据格式。
7. 诊断、测试、打包、安装与发布。

这条顺序按用户可感知的机制组织，不代表实现时可以跳过底层依赖。

## 第一轮完成标准

第一轮不是回答所有实现问题，而是做到：

- 每个 P0 问题都有明确结论，且不存在互相冲突的用户体验承诺。
- 每个子系统能描述正常流程、状态、失败与恢复，不只描述模块名称。
- 配置 schema 中每一项都能追溯到已确认行为，不保留“看起来可能有用”的字段。
- Agent Loop、上下文、权限和 TUI 共享同一套事件与状态语义。
- v0.1 非目标明确，不因参考项目功能丰富而无边界扩张。
